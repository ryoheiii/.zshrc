# 修正後の最終監査

REVISE を経て APPROVED に達した場合だけ、新規セッションで 1 回実行する。
`--resume` は使わず、通常レビューと同じラッパー・完了確認を使う。
監査用の prompt・reply・session ファイル名には `audit` を付け、通常レビューの成果物と分ける。

監査プロンプトには修正済み計画の絶対パスと要求・制約を渡し、次を依頼する。

- 部分的な修正では見えにくい計画全体の矛盾、未充足要件、状態・命名・エラー処理の不整合を確認する。
- 軽微な指摘を繰り返さず、実装を妨げる懸念を根拠付きで示す。
- 最終行を `AUDIT: PASS` または `AUDIT: CONCERNS` とする。

CONCERNS または監査失敗は成功扱いにせず、計画と懸念をユーザーへ報告する。
自動で監査ループを追加しない。
